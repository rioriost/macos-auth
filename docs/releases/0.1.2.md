# macos-auth 0.1.2

This experimental release fixes authentication lifecycle, trusted-file handling,
setup, and release-tooling defects identified in a design/code review.

## Authentication

- Socket timeouts allow Linux password fallback; malformed responses and invalid
  signatures continue to fail closed.
- Request deadlines bound transport and macOS authentication. Disconnected or
  expired requests cannot produce a late approval or terminate the agent with
  `SIGPIPE`.
- PAM requires trusted, root-owned helper/configuration/key paths. Installed
  configuration refers to installed keys, not user-owned development files.
- Agent host edits preserve restrictive configuration permissions. Socket
  startup does not overwrite ordinary files or another live listener.
- Swift and Rust agree on protocol v1 canonical authentication-method values,
  including `touch-id`.

## Setup and distribution

- SSH samples quote paths containing spaces; reconnect guidance places
  `StreamLocalBindUnlink` on the Linux SSH server.
- LaunchAgent configuration uses plist serialization and is validated before
  an existing job is stopped.
- Draft upload refuses published releases. Artifact names, checksums, and
  builder provenance are validated instead of inferred from the collector.
- The standard quality gate includes Swift, PAM, setup, and release regressions.

## Release scope and limitations

This release provides source and the signed/notarized macOS arm64 package.
Linux binary packages are not attached: build them from the `v0.1.2` source tag,
rather than using older packages that do not contain these fixes.

The project remains development-only. Automated checks do not establish
Touch ID / Apple Watch behavior on every supported macOS version, or validate
every distribution's real `sudo` PAM stack. Keep console/root recovery access
when changing authentication configuration.
